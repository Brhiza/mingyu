# 核心包能力收敛审计

## 审计目标

检查仍停留在网页层的逻辑，将可被网页、公开 API、MCP 和其他项目共同复用的纯算法迁入 `mingyu-core`，避免相同规则在多个入口分别维护。

## 本轮已收敛

### 八宅入户度数

- 新增 `analyzeBaZhaiByDoorDegree`：直接接收“站在大门处面向屋内”的指南针读数，返回坐山、朝向、二十四山、宅卦、命宅关系、八宫和测量说明。
- 新增 `getBaZhaiSitFacingFromDoorDegree`：只做统一坐向换算，适合表单预览和其他风水模块复用。
- 网页、公开 API 和 MCP 改为调用同一核心实现。

收敛理由：180° 反转、二十四山边界和宅卦换算属于领域规则，不应由每个界面自行实现。

### 统一出生真太阳时

- 新增 `calendar.resolveTrueSolarBirthTime`，统一处理公历、农历、闰月、当地时区、中国历史夏令时、跨日和早晚子时时辰索引。
- 八字、紫微和星盘统一使用该入口；原 `calculateTrueSolarTime` 与 `convertTrueSolarTime` 保留为底层和兼容入口。
- 公开 API 增加 `/calendar/true-solar-birth`，MCP 增加 `calendar_true_solar_birth`。

收敛理由：真太阳时是多个排盘共同依赖的历法地基。只共享公式但让各算法分别处理农历、夏令时和跨日，仍会产生结果漂移。

### 紫微真太阳时适配

- 新增 `mingyu-core/ziwei/true-solar-input`。
- 网页原文件改为转导核心包，不再维护日期校验、农历转换和时辰索引副本。

收敛理由：这是纯输入转换能力，不依赖 React、路由或浏览器状态，其他紫微调用方也需要。

### 星盘行运范围

- 将星盘本命、流年、流月、流日、行运落宫、返照、次限、太阳弧和相位证据迁移到 `mingyu-core/divination/astrolabe-scope`。
- 网页原模块改为转导核心包，公开 API 与提示词页面继续复用同一结果。

收敛理由：行运计算属于占星算法，不是页面展示逻辑；此前公开 API 实际依赖网页目录，说明分层位置不正确。

## 审查后不迁入核心包

### URL 查询状态与排盘链接

`query-state.ts` 负责浏览器地址栏压缩、页签和表单恢复，属于当前网页协议。它不应成为算法包公共契约。

### 本地记录、AI 设置与响应式布局

这些模块依赖 `localStorage`、窗口尺寸、浏览器事件或当前产品设置，无法作为跨环境纯算法使用。

### 结果页快捷问题和提示词交互

快捷按钮、草稿、弹窗和问题灵感是产品交互。核心包只保留可独立复用的排盘、证据与基础提示词资料，不固化当前页面流程。

### `full-chart-engine` 页面适配器

其中八字部分主要把字符串表单和页面 `Person` 状态转换为核心入参；紫微部分还负责页面范围选择和异步载荷调度。直接公开会把网页字段变成 npm 长期兼容负担。底层排盘和真太阳时能力已经分别位于核心包。

### 展示摘要与盘面组件

七政四余圆盘、八宅 SVG、占卜摘要块属于展示层。核心包提供完整结构化数据，具体视觉表达由调用方决定。

## 后续边界

- 新增历法、方位、排盘或行运规则时，先进入 `mingyu-core`，网页、API、MCP 只做参数适配。
- 依赖 React、DOM、浏览器存储、路由或当前页面文案的逻辑保留在应用层。
- 同一领域换算若在两个入口出现，应优先抽成核心函数并增加跨入口一致性测试。
- 本轮暂不修改 npm 版本、不发布包；待接口确认后再单独发布。
