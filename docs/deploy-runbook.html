① 本地构建校验 必做

1
确认构建产物
在仓库根执行，产物输出到 dist/。
pnpm --filter @temposoul/core build && vite build
# 或本沙箱等价：node node_modules/vite/bin/vite.js build
2
本地预览
核对路由 /lexicon、/login、语言切换、深空背景。
vite preview   # 默认 http://localhost:4173
本地 vite dev/preview 不执行 functions/api/auth/*，登录页会显示"部署后启用"——这是预期降级，非缺陷。

② 选择部署方式

A
方式 A：Git 集成（推荐，零 CLI）
  • Cloudflare 控制台 → Workers & Pages → Create → Pages → 连接 Git 仓库
  • 构建设置：Framework preset = Vite；Build command pnpm --filter @temposoul/core build && vite build；Build output dist
  • Node 版本用仓库 packageManager 声明的 pnpm@11 + Node 22
  • 每次 push 到 main 自动触发构建部署
B
方式 B：wrangler CLI 手动部署 
# 首次登录
npx wrangler login
# 部署（读取本仓库 wrangler.toml 的 name / pages_build_output_dir）
npx wrangler pages deploy dist
CI 已存在 .github/workflows/ci.yml（lint/type/test/build），但无自动部署步骤；部署动作由上述方式触发。

③ 启用账户认证（可选） 需 secret

1
创建并绑定 KV 命名空间 
npx wrangler kv namespace create temposoul-auth
# 把返回的 id 填进 wrangler.toml 的 [[kv_namespaces]] id
或在控制台 Pages 项目 → Settings → Functions → KV namespace bindings → 绑定 AUTH_KV。
2
设置机密 AUTH_SECRET
切勿写入仓库文件。
openssl rand -hex 32          # 生成
npx wrangler secret put AUTH_SECRET   # 粘贴上面的值
3
打开认证开关
把 wrangler.toml 的 AUTH_ENABLED 改为 "true"（或控制台 Environment variables 设同键），重新部署。
# 未绑定 AUTH_KV / 未设 AUTH_SECRET 时 /api/auth/* 返回 503，前端优雅降级

④ 首部署验证清单 上线前逐项勾选

检查项预期
首页与路由/ /lexicon /login 均 200，深空背景渲染
多语言右上角切换 zh / en / ja，文案随 locale 变化并持久化
词库页搜索 + 分类筛选 + 详情正常，种子数据可见
运行时配置页面加载 /temposoul-runtime-config.js 返回 JSON（no-store）
认证端点未启用时 /api/auth/me 返回 503 + 友好文案；启用后 register/login 可用
隐私分析默认 none，未注入任何第三方脚本
PWA/manifest.webmanifest 与 /sw.js 可访问，可安装
