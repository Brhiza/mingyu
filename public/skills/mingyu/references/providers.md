# 数据提供方抽象适配协议与降级规范（Provider Protocol & Degradation）

通用算命 Skill 的顶层决策逻辑完全独立于具体的底层引擎。无论是调用 Mingyu 本地核心库、AOV 公开 API、MCP 工具服务器，还是其他第三方排盘器或人工录入盘面，均遵循统一的抽象协议。

---

## 1. 核心 Provider 六大能力接口契约

数据提供方只负责取得、验证或转换事实，不替上层 Skill 决定用户的现实问题走向：

| 抽象能力接口 | 输入要求 | 标准化输出契约 | 失败时的收敛方式 |
| :--- | :--- | :--- | :--- |
| `discoverCapabilities` | 问题类型、时间跨度、所需精度（如需真太阳时、秒级交节） | 可用术数列表、支持的时间分辨率、流派能力与限制清单 | 标记不可用能力，保留主问题并寻找替代术式 |
| `calculateChart` | 已确认的资料（年月日时、地点、事项参数）和流派口径 | 规范化结构化盘面、时间基准、计算步骤与证据源 | 返回已确认资料与缺失字段清单，绝不补造虚假数据 |
| `normalizeFacts` | 原始盘面数据、第三方 JSON 或人工录入盘面 | 统一的事实键、时间节点、五层证据归属与证据来源 | 保留原始资料，明确标记无法唯一规范化的字段 |
| `scanDynamics` | 本命盘/基础局、目标起止时间范围、时间分辨率（年/季/月/日/时） | 按时间顺序排列的动态节点序列、引动关系与事件簇 | 降低时间分辨率并明确声明实际可信覆盖范围 |
| `generatePrompt` | 问题卡、规范化盘面事实、古典依据条目与所选流派 | 符合 `AGENTS.md` 规范的纯文本自包含完整任务书 | 改由本地模板组织结构化盘面，不伪造缺失事实 |
| `explainLimitations` | 失败类型（超时/缺少经度/格式错误）、冲突口径 | 用户可理解的判定边界与下一步建议 | 给出补齐资料、使用人工盘面或改选其他方法的明确选项 |

---

## 2. 错误处理与降级策略（Graceful Degradation）

当数据提供方发生网络超时、服务不可达或输入验证未通过时，必须保持优雅降级：

1. **保留上下文与已确认资料**：
   - 不清空用户的上下文，明确告知：“排盘计算服务当前响应超时，但您的核心诉求与输入时间已完整保留”。
2. **说明缺失影响并提供替代途径**：
   - 若真太阳时经纬度查询失败，主动降级为法定民用时排盘，并明确标注经度边界影响；
   - 若特定复合提示词接口不可用，使用标准盘面数据按 `output.md` 模板在本地为用户组织结构化答卷。
3. **支持人工录入与外部盘面导入**：
   - 当调用方已经提供了现成盘面（如用户自己排好的八字四柱或六爻卦象），Provider 仅做时间核对与有效性验证，直接进入 `normalizeFacts` 流程，不得静默覆盖。
4. **严禁将错误信息包装成玄学结论**：
   - 严禁将 HTTP 500、空数组、NaN 或默认零值解释为“大凶”、“命中无缘”等荒诞言论！
