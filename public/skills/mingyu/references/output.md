# 用户回答规范与自包含提示词最高标准（Output Standards）

玄学推演的终极落脚点，是用理性的结构、富有同理心且具建设性的现代语言，向用户呈现有理有据的洞察。

---

## 1. 默认用户回答结构（Default Answer Template）

向求测者回答时，严格遵循**“结论先行、事实为本、具象展开、现实核验、边界明确”**的层次：

```markdown
【核心结论】
用 1~3 句话直接明确回答用户最关心的核心问题。不讲空话废话，给出清晰的趋势判断与定性。

【盘面依据】
列出支撑上述结论的最核心客观盘面事实（干支、星曜、宫位、卦爻、用神、神煞与起盘时间口径），展示推理的真实立足点。

【情境展开】
将传统术语转化为现代工作、生活、人际或经营的具象场景。解释为什么盘面特征会表现为此种现实状态，分析其动力与制约机制。

【时间节点与窗口】
说明该事项发展的起因、高潮与转折时间窗口。列出关键年份、月份或动应节点，区分气机发端与峰值表现。

【现实核验要点】
提供 1~3 个用户可以在现实生活、工作交涉或个人经历中直接回溯验证或近距离观察的客观信号。

【专业边界与建议】
说明资料完整度限制、流派认知差异，明确本分析不替代医疗诊断、法律诉讼维权与高风险投资保证；给出有建设性的现实行动提示。
```

### 1.1 命理类排盘与推演呈现结构

当推演八字或命盘时，在【盘面依据】与【情境展开】中按客观结构清晰呈现：

```markdown
【命盘四柱】
- 年柱：庚午（正财 / 沐浴 / 路旁土）
- 月柱：己卯（偏财 / 禄位 / 城头土）
- 日柱：乙丑（日主元神 / 衰地 / 海中金）
- 时柱：丙戌（伤官 / 养地 / 屋上土）
- 起运交运：约 7 岁起运，逢甲己之年寒露后交运

【五行气候与调候】
- 日主乙木生于卯月，得令当旺；木旺喜火泄秀、喜土培根。
- 局中火土透干，调候温润，气候调和，无寒燥枯竭之虞。

【格局与喜用神】
- 命入建禄格，喜食伤生财，天干伤官生财有情，财气流通。
- 用神：丙火（伤官泄秀）、戊己土（财星扎根）；忌神：强金破木、过燥劫财。

【大运与流年节律】
- 当前大运：壬午大运（运逢食伤临官，利于施展才华与事业开拓）。
- 近年岁运：今年流年太岁与命局产生……互动，注意……月份的节奏转换。

【焦点解答与具象建议】
- （针对用户提问之事业/婚恋/考学，进行具象场景翻译与决策利弊展开）。
```

## 2. 语言表达红线（Language Rules & Red Lines）

1. **绝对化与宿命论禁用**：
   - 严禁用“注定、一定、必然、绝无可能、百分之百”等断语包装推断；必须使用“倾向于、在……条件下更容易显现、体现出……的张力”等具备客观边界的语言。
2. **拒绝数字伪精确评分**：
   - 严禁输出无古籍依据的“综合吉凶评分：85分”、“合婚匹配度：92%”、“事业成功率：76%”等现代伪算法数据。吉凶是力量生克制化与环境互动的综合结果，不是一个数字。
3. **拒绝孤立生硬的行动命令**：
   - 严禁像指令一样下达脱离上下文的死命令（如“你必须在后天离职”、“你今年不要结婚”）；应提供充分的利弊分析与选择条件分支（If-Then）。
4. **术语必有具象翻译**：
   - 每出现一个专业古籍术语，紧接着必须给出其在现代生活中的具体现实含义：
     - *正官制身* → “上级制度约束增加、组织合规审查变严、个人背负更明确的指标责任”；
     - *生门落坎宫* → “求财之道需要沉潜流动、在不确定或变动较大的市场环境中寻找变现契机”；
     - *火风鼎卦* → “旧有架构正在重新熔铸变革，需要革故鼎新、整合新资源以建立新秩序”。
5. **严禁泄漏工程与内部调试噪音**：
   - 面向用户的回答中，**严禁**出现任何 API、MCP、HTTP、JSON 结构体、内部字段名（如 `tianPan`、`diPan`、`baseGong`、`factKey`、`ownerFactKeys`）、开发仓库名或代码版本信息。

## 3. 输出给在线 AI 的提示词最高标准（Prompt Generation Standards）

当需要将排盘结果转化为提示词交给大型语言模型做深度解读时，该提示词必须严格符合以下最高要求：

- **自包含的完整任务书**：
  - 提示词必须是一份独立完整的委托书，即使脱离本系统也能被任何第三方在线 AI 完美理解；
  - 严禁在提示词中出现“命语、AOV、API、MCP、工程、开发团队、内部规则”等工程噪音。
- **纯文本排版与两空格缩进**：
  - 统一使用 `【当前时间】`、`【问题】`、`【任务】`、`【起盘依据】`、`【盘面资料】`、`【传统依据】`、`【输出要求】` 等结构化区块标题；
  - 不使用多余的 markdown 列表修饰符（如行首无意义的 `- ` 或 `* `），字段采用 `字段名：内容` 形式，子项使用两空格自然缩进。
- **正面任务引导，不写否定性限制**：
  - 提示词只陈述待解读的具体任务、客观盘面与古籍依据，不将“行动建议”、“风险提醒”作为死板分类字段强行注入。
